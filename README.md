# vqa-rs-kb · 视听质量检测工作站 知识分享库

这个仓库是「视听质量检测工作站」知识库页里「知识分享」子页的数据源，形态像一个论坛：

- **发帖**：新开一条 Issue（用「分享一条知识」模板），一条只讲一个知识点。
- **留言 / 纠错**：直接在 Issue 里评论。
- **加星**：给帖子点 👍 reaction。
- **举报**：用「举报条目」模板开 Issue，版主核实后打 `kb-hide` 下架。

程序端**只会读取** `index.json` 和 `items/<id>.md`，不会向这里写任何东西，也不持有任何写凭据。
所以这里的提交、评论、加星都必须由人在 GitHub 页面上完成。

## 一条帖子怎么才会出现在程序里

每小时（以及帖子变动时）由 `.github/workflows/aggregate.yml` 跑一次 `scripts/aggregate.py`：

1. 拉取所有带 `kb-submit` / `kb-approved` 标签的 open issue；
2. 按模板解析出标题、类型、标签、来源、正文；
3. 自动校验：标题 ≤20 字、正文 40–600 字、陈述句、不含链接 / 代码块 / 指令类表述；
4. 通过的打上 `kb-approved` 并进 `approved`，没通过的留在 `pending`（**只能看，不能采纳**）；
5. 计算热度名次，重写 `index.json` 与 `items/*.md` 并提交。

所以从发帖到出现在程序里，最长大约一小时。想立刻生效，版主手动跑一次 workflow 即可。

## 名次怎么算

```
score = log(1 + 星数 + 0.5 × 留言数) / (1 + 发布天数 / 45)
```

- 对数：第 100 颗星的价值远低于第 1 颗，刷星收益递减；
- 45 天衰减：老帖自然下沉，新帖有出头机会；
- `pins.json` 里点名的条目置顶，不受公式影响，最多 3 条；
- 程序里还有「最新」「我用过的」两档排序，用户自己切。

## 写一条合格的帖子

- 一条只讲一件事，标题就能当检索词用（「矩阵主备切换耗时」而不是「矩阵那些事」）。
- 正文 40–600 字，陈述句，写清数值、条件、边界。别写「可能」「大概」「看情况」。
- 不写内部 IP、账号、人名、电话；需要举例用「A 区」「某频道」。
- 不贴链接、代码块、图片。
- 来源写单位与月份：`河北广电 平台运维部 · 2026-11`。

## 免责

条目由社区投稿，仅通过基础规则校验，不代表任何单位的正式口径。程序里采纳前请自行判断；
不同单位阈值可能不同，程序会把冲突条目标出来交给你裁决，不会静默覆盖你已有的知识。
